# 15 · Troubleshooting by symptom

## The app looks like an older version

Check the native title and `/health` version, process and profile. A downloaded EXE, installed source copy and another extracted ZIP can all exist at once. Starting a new copy may focus the existing single instance rather than launch the new code. Do not conclude the repository was lost from appearance alone. Close normally and reopen the intended build. Compare release manifests and source revision before editing anything.

## History or gear appears missing

Check the profile and browser origin before restoring a backup. A disposable development profile intentionally starts empty. Browser gear/planner state can differ by port or browser even when native history is unchanged. Export or preserve both states before investigation. Inspect SQLite integrity on a copy. Avoid resets and automatic history merging.

## Tool labels are visible but no current tool

Open Tool Reader → Live OCR Reader. If the capture misses labels, inspect window bounds, camera movement and discovery. If numeric fields are unreadable, inspect raw text and two-pass agreement. If multiple verified tools exist, inspect Place Mode geometry and ambiguity. If one is selected by position but use is unconfirmed, check that crafting is actually consuming durability. A stationary tool should not produce fake decrease evidence.

## Quest counter is stuck

Open Quests → Live OCR Reader and verify the intended heading/objective is in the actual input. A covered widget is unavailable even if you know it exists behind a browser. Check whether the number changed lines, whether the Guild heading was recognized and whether the two numeric reads agree. Last-seen state may be retained deliberately after an uncertain frame. A genuinely new mission requires rollover evidence or the explicit Next Quest control; do not relax rollover to accept every lower number.

## Loot is missing

Inspect the loot OCR reader first. Check feed selection, complete personal message rows, actual capture gap, overlap loss, unmatched names and uncertain quantities. If an item is parsed but not recorded, inspect consensus and deduplication. If recorded but not valued, inspect item identity, quote source and region. A silver discrepancy does not by itself prove the silver formula is wrong.

## Timer or silver does not update on the website

Verify the browser is using the paired planner URL, the bridge is healthy, optional sharing is enabled and the timer attached to the current history identity. Check acknowledgment state and event boundaries. A completed timer is intentionally frozen. Excluded time should pause observed-rate accumulation; it should not erase previously recorded value. An unpriced item stays visible in a partial total.

## OCR is slow

Check image dimensions and enabled readers before adding threads. Look at elapsed scan time, pass count, cache hits and rediscovery. Discovery costs more than steady cropped tracking. Simultaneous debug viewers add image conversion/rendering work while open. An idle provisional tool can still schedule frequent checks. Measure the relevant case and preserve deadlines; never disable rejection rules just to make the result arrive faster.

## A build passes locally but fails in CI

Compare Python/Tesseract versions, generated assets, Windows font availability and paths. CI starts clean and has no private captures or caches. Public tests must not require a user's saved image. Run generated fixtures and inspect the extracted package report. Ensure the new source file is included by packaging and that the actual embedded planner was regenerated when needed.

## Reporting a useful issue

Provide version/source identity, feature, expected result, actual result, capture availability, timing and a minimized reproduction. Mark whether the evidence is live or replayed. Share real screenshots only intentionally and after considering names/chat shown in them. Do not attach the whole user profile or private history to a public issue.
